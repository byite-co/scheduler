함수 본문에 권한 검사 **0줄**:
```sql
update homework_submissions
   set ai_verdict = p_verdict, ai_confidence = …, ai_reason = p_reason
 where id = p_submission_id
```

**왜 anon 만 남아 있었나** — 원본(`20260624000000_m4_homework_ai_check.sql:41-43`)은
`revoke ... from public` + `revoke ... from authenticated` + `grant ... to service_role` 이었다.
`revoke ... from public` 은 Supabase 기본 권한(ALTER DEFAULT PRIVILEGES)이 **롤별로** 부여한
grant 를 지우지 못한다. authenticated 는 명시적으로 적혀 있어 빠졌고, **anon 은 목록에 없어서
그대로 남았다.** 같은 실수가 `20260806000000`(mock 구독 RPC)에서 이미 한 번 있었는데,
이 함수는 그때의 점검에서 누락됐다.

**after** (실측)

| grantee | privilege |
|---|---|
| postgres | EXECUTE |
| service_role | EXECUTE |

anon·authenticated 모두 없음. 추가로 **함수 안에 호출 주체 검증**을 넣었다(이중 방어):

```sql
if coalesce(auth.role(), 'service_role') <> 'service_role' then
  raise exception 'service_role_required';
end if;
```

| 호출 주체 | `auth.role()` | 결과 |
|---|---|---|
| anon 키 | `'anon'` | 거부 |
| 사용자 토큰 | `'authenticated'` | 거부 |
| service_role 키 | `'service_role'` | 통과 |
| JWT 없음(psql·Management API·마이그레이션) | `null` → coalesce | 통과 |

`null` 을 통과시키는 이유: 운영 점검·데이터 보정을 막으면 안 된다. 그 경로는 이미 DB 직접
접근 권한이 있는 사람만 쓸 수 있어 새로 여는 문이 아니다.

## 2. 음성 테스트 결과

anon key·실제 학생 토큰으로 PostgREST 직접 호출. 대상은 **실제로 존재하는** submission id 다
(A1 에서는 존재하지 않는 id 로만 확인했다).

| # | 실행 명령 | 기대 | 실제 | 판정 |
|---|---|---|---|---|
| 1 | `curl -X POST '…/rest/v1/rpc/apply_homework_ai_verdict' -H 'apikey: <ANON_KEY>' -d '{"p_submission_id":"<실제 SUB_ID>","p_verdict":"pass","p_confidence":1,"p_reason":"…"}'` | 함수 본문 실행 전 거부 | **401** `42501 permission denied for function apply_homework_ai_verdict` | ✅ 차단 |
| 2 | `curl -X POST '…/rest/v1/rpc/apply_homework_ai_verdict' -H 'apikey: <ANON_KEY>' -H 'Authorization: Bearer <STUDENT_TOKEN>' -d '{…}'` | 거부 | **403** `42501 permission denied for function apply_homework_ai_verdict` | ✅ 차단 |
| 3 | `curl -X POST '…/rest/v1/ai_recommendations' -H 'Authorization: Bearer <STUDENT_TOKEN>' -d '{"student_id":"<S_ID>","week_start":"2026-08-10","subject":"math","recommended_hours":5,"reason":"probe"}'` | 실패 (A1 에서는 **201**) | **403** `42501 permission denied for table ai_recommendations` | ✅ 차단 |
| 3b | `curl '…/rest/v1/ai_recommendations?select=*' -H 'Authorization: Bearer <STUDENT_TOKEN>'` | 본인 행 조회는 허용 | **200 `[]`** | ✅ 의도대로 |

**1·2 는 `42501`(권한 거부)이다.** A1 에서 나왔던 `400 P0001 homework_submission_not_found`
(= 본문이 실행된 증거)가 더 이상 나오지 않는다 — 요구된 기준을 그대로 충족한다.

### #4 — 정상 경로 확인 결과: **정상 경로가 이미 깨져 있다 (내 변경과 무관)**

AI 호출 없이 service_role 로 Edge Function 과 같은 RPC 를 직접 호출했다(새 과금 없음).

| 단계 | 결과 |
|---|---|
| `start_homework_check_attempt` | **성공** — attempt 생성됨(`status='processing'`) |
| `record_homework_check_observation` | **실패** — `column "status" is of type check_attempt_status but expression is of type text` |

원인은 `supabase/migrations/20260807030000_homework_check_observation.sql:87`:

```sql
set status = case when p_discard_reason is null then 'completed' else 'failed' end,
```

CASE 의 두 분기가 모두 무형 리터럴이라 결과 타입이 `text` 로 정해지고, Postgres 는
`text → check_attempt_status` 를 암시적으로 캐스팅하지 않는다. **이 함수는 호출될 때마다 실패한다.**

**내 변경과 무관하다는 근거**

- 이 브랜치의 diff 에 `record_homework_check_observation` 문자열이 **0건**
  (`git diff main | grep -c` → 0). 변경 파일은 `m5Screens.tsx` · `featureFlags.ts` · `schema.sql` 뿐이다
- 해당 파일의 커밋 이력은 `9bc4c32`(2026-08-07) **한 번뿐** — 이후 수정된 적이 없다
- 실패 지점이 함수 본문의 UPDATE 문이며, 내가 만진 두 객체(`apply_homework_ai_verdict`,
  `ai_recommendations`)와 접점이 없다

**왜 지금까지 안 잡혔나** — 이 함수를 실제로 **실행하는 테스트가 없다.**
`m4.schema.test.ts:62-64` 는 함수 존재·권한을 문자열로 확인할 뿐이고, Edge Function 은 실패 시
`fail_homework_check_attempt` 로 넘겨 attempt 를 `failed` 로 마감한다 — 즉 겉으로는
"AI 검사 실패"로만 보이고 원인이 드러나지 않는다.

**고치지 않았다.** 이번 작업의 수정 범위는 세 항목뿐이라는 규칙에 따른다.
고칠 때는 `'completed'::check_attempt_status` / `'failed'::check_attempt_status` 로 캐스팅하면 된다.
⚠️ **AI 검사 기능 자체가 현재 동작하지 않는 상태**이므로 우선순위가 높다.
